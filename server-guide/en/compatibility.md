# Compatibility matrix

[简体中文](../zh-cn/compatibility.md)

What this build is tested against, what it integrates with, and what it deliberately does not support.
**Verified** means the path was exercised in a recorded round (see the workspace `verification-records/`);
**supported** means the code path exists and is expected to work but has not been re-verified recently.

## Core

| Item | Version / range | Status |
| --- | --- | --- |
| Server | Paper or Folia 1.21.5+ | supported; Folia scheduling is region-owned |
| Java | 21 for 1.21.5–1.21.11, 25 for 26.1+ | supported |
| CraftEngine | compiled against 26.9.1, declares 26.8.2+ | supported; symbol-checked against 26.8.2 / 26.9 / 26.9.1 / 26.9.2 and 26.10 snapshots |
| Folia turn-level region work (pot ticks, hopper transfers, GUI writes) | current Folia build | **not yet verified on a live Folia server**; use the manual checklist in [Troubleshooting](troubleshooting.md#folia-concurrency-stress-checklist) |
| Resource pack | required, generated by CraftEngine | supported; players need no client mod |

## Optional plugin integrations

| Plugin | Direction | What it enables | Status |
| --- | --- | --- | --- |
| PlaceholderAPI | FD → PAPI | `%farmersdelight_buff_*%`, `%farmersdelight_api_version%`, `%farmersdelight_discovery_enabled%`, `%farmersdelight_discovered_cooking_pot%`, `%farmersdelight_discovered_cutting_board%`, `%farmersdelight_discovered_total%` | supported |
| UltimateAdvancementAPI | FD → it | advancement tab UI; an unpatched build without the layout overload disables FD's tab instead of crashing | supported |
| AuraSkills | FD → it | cooking-pot skill XP (configurable rewards) | supported |
| Leveler | FD → it | cooking-pot XP through CE's provider | supported |
| MMOItems, ItemsAdder, Nexo, Oraxen | FD ← them | external item sources via CraftEngine `ItemSource`; add the provider name to `external-item-sources` to recognize held items | supported |
| WorldGuard | FD → it | master `farmersdelight-use` flag plus one flag per station; addons can register their own flag | supported |
| other land/claim plugins (GriefPrevention, Lands, Towny, Residence, …) | FD ← CE | checks run through CraftEngine's bundled AntiGriefLib provider, so station use and harvesting respect claims | supported |
| Kaleidoscope Cookery | FD ← it | right-clicking a cooking pot with a recorded recipe item fills the pot; CE-pack `c:` tag members are bridged into FD's tag registry | supported (auto-fill only; no recipe or knife registration into Kaleidoscope) |
| Brewin' And Chewin', End's Delight, Crabber's Delight, Barbeque's Delight | FD ← addons | addon content and stations through the FD api | supported (each addon is a separate plugin) |
| VillagersDelight | standalone | farmer villagers plant/harvest CraftEngine crops, social food sharing | supported (not required) |

## Not integrated — and why

| Area | Reality |
| --- | --- |
| Bedrock / Geyser clients | Custom items, blocks and models exist only in the Java resource pack; Bedrock players cannot see them. |
| Client mods (JEI/EMI) | Not applicable: the recipe viewer and editor are server-side GUIs. |
| Map renderers (Dynmap/BlueMap) | Custom blocks are CraftEngine states, not map-renderable vanilla blocks. |
| CoreProtect / Prism logging | FD block changes are not logged through those plugins; use their own custom-block support if needed. |
| Economy (Vault) | No economy hooks are implemented. |
| Quest plugins (BetonQuest/Quests) | Use the `api.event` classes; no prebuilt integration ships here. |
| MythicMobs / ModelEngine | Models come from CraftEngine; there is no direct hook. |
| Permission plugins | Only the `farmersdelight.*` permissions are used; no LuckPerms-specific code. |

## Verification policy

* CI gates every change: build + the thirteen repository checks (`tools/run_all_checks.py`).
* Live rounds are recorded outside this repository (`verification-records/`) and are what makes a row
  "verified" instead of "supported".
* The Folia concurrency checklist is manual by design; the repository checks cannot prove region ownership.
* "Supported" rows are expected to work but may not be re-run for every release. Treat the status column as the
  honest state, not a marketing claim.
